# `.pulse` 导入：格式依据与支持边界

核实日期：2026-10-18。`.pulse` 是 App 的曲线描述文件，不是已有 JSON 帧数组改扩展名。官方公开资料可以确认播放模型和 V3 帧协议；文件语法、索引表来自公开导出样本及分享工具作者的一手研究，不能宣称为官方完整文件规范。

## 依据

- [官方自定义波形帮助](https://www.dungeon-lab.cn/instructions-cn.html)：一个波形包含连续小节及末尾休息；每个形状点的基础时间为 100 ms；小节完整重复脉冲元，次数向上取整；介绍四种频率模式和锚点。
- [官方 V3 协议，固定提交](https://github.com/dungeonlab-open/dglab-bluetooth-protocol/blob/045720d5c5ee4879e25b7bad555c962f97ed423f/coyote/v3/README_CN.md#通道波形频率--通道波形强度)：频率编码、幅度范围以及 25 ms / 100 ms 数据组织；设备通道强度与波形数据分开设置。平衡参数另属 BF 指令。
- [Fangs：3.4.4 新版波形数据格式解析，2025-02-13](https://forum.dg-bbs.com/d/18-344-xin-ban-bo-xing-shu-ju-ge-shi-jie-xi)：App 3.4.4 导出语法、最多 10 小节、休息与倍率、频率及新版时长索引表。第三全局字段在该原始研究中仍未确定用途。
- [Fangs 的分享工具](https://dg-bbs.com/share)：公开页面源代码具有相同索引表，并区分含全局参数的新格式和不含参数的旧格式；名称单独保存在分享链接/下载文件名中。
- [公开 `.pulse` 样本库，固定提交](https://github.com/zakotoys/dglab-pulse-collect/tree/f42b5805dd964be5ae499156c071a142b86c7cb5/pulses)：用于只读核实实际词法结构及小数幅度。该库自称为非官方收集。

## 已确认的文件结构

```text
Dungeonlab+pulse:<rest>,<speed>,<appParameter>=<section>[+section+<section>...]
section := <freqA>,<freqB>,<duration>,<mode>,<enabled>/<value>-<anchor>[,<value>-<anchor>...]
```

| 字段             | 可确认含义                                                             |
| ---------------- | ---------------------------------------------------------------------- |
| `rest`           | 所有启用小节结束后休息，数值 × 100 ms；不是各小节之间的间隔            |
| `speed`          | 播放倍率，已知值 1、2、4；形状点分别占 100、50、25 ms                  |
| `appParameter`   | App 附加参数；有公开样本出现 0、1、8、16，尚无可靠映射到 V3 设置的依据 |
| `freqA`、`freqB` | 频率滑块索引 0..83，映射结果是周期毫秒数，不是 Hz                      |
| `duration`       | 小节目标时长索引 0..99，使用下述新版表                                 |
| `mode`           | 1 固定，2 节内渐变，3 元内渐变，4 元间渐变                             |
| `enabled`        | 0 跳过该小节，1 顺序播放该小节                                         |
| `value`          | 0..100 的相对波形幅度，可含小数；不是设备通道强度                      |
| `anchor`         | 0 自动点，1 编辑锚点；文件已经包含自动点的数值                         |

单文件描述一条波形。`+section+` 连接的是同一波形的连续小节，不是多个独立波形。文件内容没有可信的名称字段，导入名称取文件名并去掉 `.pulse`。

频率表可按以下片段依次拼接，范围两端均包含：

```text
10..49 step 1; 50..78 step 2; 80..95 step 5; 100..190 step 10;
200,233,266,300,333,366; 400..550 step 50; 600..1000 step 100
```

新版时长表以 100 ms 为单位，依次拼接以下片段（共 100 项）：

```text
1..49 step 1; 50..78 step 2; 80..95 step 5; 100..190 step 10;
200,234,266,300,334,366; 400,450,500,550; 600,700,800,900;
1000,1200,1400,1600,1800; 2000,2500,3000
```

小节在未应用播放倍率的逻辑时间中，按 `ceil(目标时长 / (点数 × 100 ms))` 次重复完整脉冲元。固定频率转换时，每点占 `4 / speed` 个 25 ms 采样。频率依官方分段压缩规则向下量化为 10..240 的字节；相对幅度向下量化为 0..100 字节，绝不转成通道强度。

## 本次保守支持范围

支持含三个全局数值的新格式和固定频率小节（`mode=1`，或模式 2..4 但频率 A/B 相同）。按文件顺序处理全部小节和启用开关；有范围错误、截断或超限时整条导入失败。App 附加参数不应用到设备，界面明确说明只导入频率、相对幅度及节奏，设备强度和平衡沿用当前设置。

完整波形周期（所有启用小节加末尾休息）必须是 100 ms 的整数倍。不同小节可在同一帧中连续排列，不单独补齐；若最终还剩 25、50 或 75 ms，则明确拒绝并提示调整点数/倍率，不补静音、不截断、不额外重复，以免改变循环节奏。原始文件上限 5,000,000 字节，展开后上限 100,000 帧（10,000 秒）；所有限制均在写入波形库前检查。

暂不接受频率 A/B 不同的渐变模式 2..4。原因是公开实现存在索引插值与物理周期插值、端点采样等差异，缺少足够的 App 实际输出对照；不使用固定频率近似替代。错误提示引导改用已展开的 V3 JSON 帧。此限制也适用于含任意不支持启用小节的文件，避免部分导入。

不含 `<rest>,<speed>,<appParameter>=` 的旧文件、名称前缀的社区方言、QR URL、gzip/ZIP、V2 帧及未知容器需明确拒绝，建议在相应 App 中重新导出或使用 V3 JSON。`.pulse` 没有独立的显式版本号，所称“3.4.4 格式”是来源/语法范围，不代表能够识别任意未来版本。当前未发现必须为这种明文格式解压的证据。

## 最小夹具的来源

[`tests/fixtures/pulse/minimal.pulse`](../tests/fixtures/pulse/minimal.pulse) 是合成夹具，由公开的[三角形导出样本](https://github.com/zakotoys/dglab-pulse-collect/blob/f42b5805dd964be5ae499156c071a142b86c7cb5/pulses/pulse-006/pulse-%E4%B8%89%E8%A7%92.pulse)缩减为两个整数幅度点，并把时长索引改成 1（200 ms）。它保留真实导出语法，不携带个人数据。

索引 0 对应 10 ms 固定周期，幅度依次为 20、40，各保持 100 ms，因此预期为两帧 `0A0A0A0A14141414`、`0A0A0A0A28282828`，总时长 200 ms；`minimal.expected.json` 保存这一可独立计算的预期。夹具不证明渐变、未知字段或所有 App 版本的互操作性。

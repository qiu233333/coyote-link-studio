# 实施验证记录

日期：2026-10-18。环境：Windows、Node.js 24.19.0、pnpm 11.25.0、Microsoft Edge（Playwright 驱动）。

## 构建与静态检查

- `pnpm typecheck`：通过。
- `pnpm build`：TypeScript、Vite 前端与 eve 本地运行时构建通过。
- `git diff --check`：通过。
- 前端仅使用本地字体与头像资源，不依赖外部字体请求。

## 自动化测试

`pnpm test`：26 项全部通过，覆盖以下边界：

- 官方 SDK 的 V3/V4 模拟中继：扫码内容、发现和选择设备、强度转换、短波形发送。
- 显式模拟设备、波形协议和上限校验。
- 急停清理顺序、停止回传确认、超时不重试、不虚构归零。
- 启动、暂停、连接与急停的并发；旧响应不能恢复输出。
- 三类控制权互斥、锁定期间修改拒绝、启动幂等。
- AI 反馈取消旧决策、暂停修改范围、运行时中断后停止。
- 后台截止、暂停期间截止、重启标记中断且不恢复。
- 固定随机种子、授权行为、阶段保持/间隔/渐变、列表跳项和暂停恢复。
- 本机 Host/Origin/会话验证、WebSocket 实际推送、API Key 加密与脱敏。
- 真正的 eve 子进程通过本地 OpenAI 兼容接口桩测试聊天、工具调用、草稿、范围拒绝、内部鉴权及取消。

## 浏览器端到端

运行 `pnpm verify:browser`。测试使用临时数据库、显式模拟设备和本地兼容模型接口桩，不使用真实 API Key 或真实设备。

实际通过六组流程：

1. 设置页保存配置并测试聊天与工具调用。
2. 控制台连接模拟设备，设置通道上限，单波形开始后观察到非零回传，再停止。
3. 普通 AI 控制确认启动、文字反馈、暂停、修改范围、恢复和手动接管。
4. AI 上锁任务生成草稿、修改、确认开启，检查控制台只读和后端写请求返回 423。
5. 上锁期间发送反馈，使用急停终止，观察到通道归零。
6. 检查窄屏布局无横向溢出，紧急停止可见。

本轮浏览器验证产生 8 次实际本地模型接口请求，未预期的页面异常、控制台错误和 HTTP 错误均为 0。预期的锁定写请求 423 被单独记录。

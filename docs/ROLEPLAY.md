# 情景演绎

选择一个角色，创建自己的玩家身份和开场情景，正常回复剧情即可。AI 每收到一次玩家消息回复一轮，根据回答推动事件、角色关系和目标；不在玩家未回答时自行续写。游戏不限时，支持跨天继续。

## 从角色卡开始

进入「情景演绎」，创建或导入角色，然后点击「开始演绎」。角色卡包含头像、人设、背景、说话风格、开场、备选开场、对话示例、世界设定与联动风格。每个故事使用角色快照，编辑或删除库中的卡片不影响旧故事。

「角色卡格式」提供本站 JSON 示例、字段说明、复制模板、下载、给其他 AI 的制作说明，以及粘贴校验。格式为 `spec: coyote_roleplay_card`、`version: 1`，数据定义与校验在 `shared/roleplay.ts`。角色姓名必填，文本资料可以为空；`avatar` 是 `null` 或内嵌 PNG/JPEG/WebP 数据，不使用本机路径或外部链接。角色卡不包括聊天、设备权限、脚本或密钥。

### 第三方兼容清单

| 来源                           | 支持方式                                                              |
| ------------------------------ | --------------------------------------------------------------------- |
| 本站 JSON                      | 本地严格校验，直接进入编辑器，保存前可修改                            |
| V1 根对象 JSON                 | 本地读取，AI 转换为本站字段                                           |
| V2 `chara_card_v2` JSON        | 本地读取 `data`，AI 转换                                              |
| V3 `chara_card_v3` JSON        | 本地读取 `data`，AI 转换                                              |
| PNG 角色卡                     | 检查签名、尺寸、块长度、CRC，提取 `chara` / `ccv3`；两者存在时优先 V3 |
| PNG 文本块                     | 支持 tEXt、zTXt、iTXt 中的 Base64 JSON；限制解压后的大小              |
| 普通 PNG/JPEG/WebP             | 可作为角色头像；不从纯图片推断人设                                    |
| `.charx`、压缩容器、第三方脚本 | 首版不支持，请先在原软件导出 JSON/PNG                                 |

第三方导入先显示提取的原始资料及兼容提示。点击「使用 AI 解析」后才向当前配置的 AI 发送文本资料；头像保留在本机。转换后的字段可编辑，原文及无法迁移内容可展开查看；点击保存后才入库。失败可重试或手动整理。

支持 `{{char}}`、`{{user}}` 称呼替换。世界书整理为背景文本，不运行动态触发引擎。其他宏、扩展脚本和系统提示覆盖不执行，保留原始预览并提示。不会自动下载外部头像或资源。角色文件最多 20 MiB、提取文本最多 128 Ki 字符且受模型上下文预算限制；超限报错，不静默截断。编辑器上传头像最多 10 MiB。

## 设备联动

默认可以只聊剧情。启用联动时，确认 A/B 独立强度范围、最大变化速率、允许波形，以及双通道、渐变、AI 休息权限。新联动的确认页默认勾选 A/B、波形库中的全部波形及三项权限；各通道最低强度为 0，最高强度取打开确认页时最新上报的设备上限，变化速率为 5/s。可以修改后再确认；打开页面不会输出，确认后的初始输出仍为零。修改正在运行的授权时载入原范围，不使用默认值覆盖已有选择。没有游戏截止时间、单轮时长或单次动作倒计时。

开场不输出，第一条正常回复才触发 AI 调整。模型仅可提出：

- `keep`：保留全部输出参数与波形游标。
- `update`：只更新指定通道的指定字段，未提供的字段保持原值。
- `rest`：对指定的授权通道归零休息；后续玩家回复才会触发新的调整。

每路可以独立更新目标强度、波形和授权内变化速率。渐变从当前执行水平开始，到达目标后持续保持。换波形在下一短窗口切换，不先归零；只调强度不重置波形位置。传输仍以约 500ms 的窗口循环补帧，窗口不是输出时限。

发送消息、等待回复、摘要处理、取消生成、正常回复完成，以及临时模型错误重试，都不主动归零。后台保留最近的有效输出。页面关闭后持续联动，重新打开故事恢复真实状态；不产生额外的模型续写。

暂停、结束联动、急停或不可恢复故障会停止并确认归零。暂停后可以继续纯文字聊天；恢复后不重放旧参数，下一条消息再产生新建议。修改授权会先暂停归零，确认新版范围后保持暂停。发生停止未确认时，禁止重新输出。

模型超时、限流、传输错误或临时服务错误，初次失败后最多重试 20 次，间隔 1 秒，重试中保持输出。新消息可取消旧生成，连续恢复额度在有效回复后重置。耗尽、非法工具结果、越界、截断或 AI 运行时故障会终止联动。设备断线、状态过期和指令故障独立处理。服务重启标记旧运行及未完成回复为中断，不自动重放输出。

当前强度以设备回传为准。故事中的台词与设备执行记录分开显示。

### 联动开启后强度一直为零

先展开回复下方的控制记录。`keep` 只保留已有参数，初始目标 A/B 都为零时不会自行启动输出。记录会明确区分「保持原参数」「参数更新已提交」和「归零休息」，模型提供的简短 `controlReason` 显示为独立的联动说明。旧故事记录也会按原动作显示正确标签。

展开「设备详情与授权范围」，确认当前故事正在联动，且参与通道的最高强度大于零。授权为零、暂停或纯文字模式都不能输出非零。设备有非零授权时，玩家只需正常回复剧情：AI 应从授权范围低端自主启动，再根据情节、玩家表达和实际回传调整；不要求在剧情里额外下达强度命令。角色卡中的「所有互动为虚构」「不涉及实际硬件」属于叙事资料，不能替代或撤销用户在联动确认页给出的权限；角色也无需在台词中谈及设备。玩家明确要求保持或休息时仍应尊重。

系统不会把 `keep` 强制改成增量，也不会为制造变化而每轮提高强度。模型仍可能合理维持或休息，可通过本轮联动说明判断；所有更新继续经过后端边界验证。提示与记录修复同样适用于已有故事，无需修改角色快照或重新建故事。升级后须重启后台及 AI 工作进程才能加载新提示；先结束当前联动，再使用同一工作目录的 Stop / Start，重新连接并确认授权。

## 六部分记忆与本地数据

| 部分           | 内容                                                           |
| -------------- | -------------------------------------------------------------- |
| 角色与玩家设定 | 角色快照、玩家称呼、身份、双方关系                             |
| 近期剧情       | 当前事件、进展、冲突与待处理线索                               |
| 近期对话       | 默认最近 20 条原文，按上下文预算逐步减少，至少保留最新玩家消息 |
| 剧情背景       | 开场、世界规则、场景与重要人物信息                             |
| 长期剧情摘要   | 重要事件、转折、目标与未解决伏笔                               |
| 长期对话摘要   | 约定、偏好、称呼和关系变化                                     |

旧消息按连续范围串行归档，保存摘要的起止消息序号，累计记忆再进入下一轮。完整原文始终保留。摘要不会改变设备参数或授权，也不作为验证现实行为的证据。各故事完全隔离。

数据存于本机 SQLite，角色卡、故事、逐条消息、轮次、幂等记录和摘要归档分别保存，不将完整历史放进全局状态或每秒运行快照。历史分页读取，可以导出文字记录。删除故事需先结束联动并等待生成取消完成。

## 接口与开发验证

新增 `/api/roleplay`：`/cards` 管理角色；`/cards/import/extract` 接收 `application/octet-stream` 文件，`/cards/import/convert` 生成转换预览；`/card-format` 返回统一模板；`/sessions` 管理故事；`/sessions/:id/messages` 幂等提交或分页读取；`/turns/:turnId` 查询生成状态；`/link/start|pause|resume|bounds|stop` 管理设备授权。写接口继续使用同源会话和 `X-Coyote-Request`，急停沿用 `/api/emergency-stop`。

`ControlSession` 区分有限时与演绎无限时类型，只有 `owner: roleplay` 使用 `deadlineAt: null`。输出变更由共享控制器验证后原子提交；推理取消与设备输出生命周期分开，旧轮次无法覆盖新轮次。所有 AI 请求继续经过受鉴权保护的 eve 内部入口，只有业务工具权限，凭证不进入提示词、前端持久化或日志。

```powershell
pnpm test
pnpm typecheck
pnpm build
pnpm exec tsx scripts/verify-roleplay.ts --browser
pnpm exec tsx scripts/verify-roleplay.ts --deepseek --browser
pnpm exec tsx scripts/verify-roleplay.ts --deepseek --thinking --browser
```

验收脚本使用临时数据库、独立 eve 工作目录、本地 HTTP 模型桩和模拟设备，监听随机端口，不读取或修改主工作区生产配置。结果及截图位于 Git 忽略的 `artifacts/roleplay/`。`--serve` 可保持隔离验收环境供人工检查，结束时清理临时目录。

真实模型和硬件需要另外联调。首版不包含上锁演绎、多角色同场、语音、动态立绘、固定分支引擎或第三方脚本执行。

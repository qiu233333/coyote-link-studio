运行记录和构建记录的源指纹均为 `95ebc74a4d1879754b7df58b343a23f0949ae259dd547f36a5dbf7b378d14fdf`。使用仓库的构建指纹算法、Node 24 和历史 Git 文件内容在内存中重算，准确匹配 `f354ec8`。服务于当日 15:36（北京时间）启动，早于 17:04 提交的 `74d5036`。因此现场后台尚未加载最新 AI 异常中断修复；不能把该次实际故障归因于已经运行最新版。首次状态查询的工具输出范围过宽，后续审计改为严格字段白名单；提交记录只包含设备和停止证据，未读取安装密钥或调用真实模型。

## 隔离复现与修复

- 启动器的 `idleWithoutDevice` 直接依赖初始 GET 判断退出，绕过控制器取消和动作代次失效。现统一调用急停，再读取最终状态；缺字段、字符串布尔值、非数值零、单路非零、活动运行和未完成停止均不能授权结束进程。基线启动器在临时副本执行新增 idle 回归，按预期失败：未调用控制器停止。
- V3 的 APP 在强度已经为零时可能不再发送变化事件，原实现每次强制等待新事件，导致安全的重复停止被误判。现只复用同连接中的新鲜、实际双零回传，而且其后没有强度操作或未决强度指令；证据过期、曾有未知操作或有效停止故障时仍要求新证据。
- V3 仅完成配对、尚未收到首条强度回传时，不能算作“从未连接待机”。隔离中继先复现了错误放行；现从真实配对事件记录会话与 APP 身份，发送停止命令后仍等待真实强度回传，不用默认零值代替。
- V4 的局部属性或单路回传原来可能刷新合并后两路值的共同时间，不能证明另一通道新鲜。现分别记录真实 A/B 回传；停止必须取得清队列 ACK、A/B 归零 ACK，再从本次归零后的关联查询取得完整双零结果。元数据更新、单路回传和旧心跳迟到结果均不能代替本次确认。
- 完成的停止证明仅在没有后续输出及非零回传时可复用。设备重新附着会使旧证明失效；断线保留最后真实读数。初次待机且从未形成设备会话可直接确认本实例没有输出；未确认的断线残留不能假装成初次待机。
- 多次停止共享当前确认过程；停止立即废弃旧启动、旧模型决策和设备动作。连接或选择设备正在取消时，必须等清理完成并重新确认最终设备状态，不能沿用先前 idle 结果。
- 未确认和进行中的停止状态持久保存，避免重启后被新的空闲驱动抹掉。故障任务仍保持终止；恢复连接、再次急停或关闭网页都不会自动恢复运行。`stopReason` 返回具体失败原因，启动器保留后台及服务记录，提示先在 APP/设备停止输出、恢复原连接后重试。
- PID、Node 可执行路径、创建时间和本项目绝对入口校验继续保留；结束进程前再次校验，只有确认安全后才通过 `/T` 结束受管进程树。

使用 `74d5036` 的设备实现，在隔离副本执行四项新增关键回归，四项均按预期失败：初始待机停止、V3 已双零但没有变化事件、V4 单路/元数据错误刷新另一路新鲜度，以及旧心跳双零回包替代本次查询缺失的回传。修复后这四项及完整设备回归通过。这些是独立复现的代码问题，不能据此反推现场硬件一定发生了其中某种时序。

## 实体设备限制

没有实测硬件，不能保证官方 APP 在所有版本和断线时序中都发送停止所需的回传。V3 没有清队列 RPC ACK，也没有强制读取强度的查询接口；只能依据协议支持的清队列发送和实际双通道强度回传，不能声称获得了硬件层清队列 ACK。缺乏足够证明时仍保留后台。

设备协议的 APP/槽位标识不能提供跨重新配对的全局硬件身份证明。历史停止未确认时，换 APP、换设备、切换模拟器或丢失身份元数据不能作为原设备的停止确认。旧版中断/未确认记录缺少原设备身份时，升级也不会自动解除故障；缺少可靠身份的情况会继续保留后台。没有加入忽略确认的强制退出开关。

本分支不合并、不推送、不发布，也不自动替换或重启当前实际服务；是否合并由用户决定。
